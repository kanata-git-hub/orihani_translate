# 실제 앱 음성 비교

소유자 전용 `/app/voice-compare`에서 한국어↔일본어를 시험합니다. 기존 앱의 음성 모델, 문자·이미지 번역과 `/live` 메시지 형식은 유지합니다.

- 마이크 또는 최대 30초 녹음 파일을 한 번 입력합니다. 같은 PCM16 mono 24 kHz를 두 모델에 사용하며 서버가 입력 SHA-256을 기록합니다.
- GPT-Live 1은 녹음 중 200 ms 단위로 입력을 받고, Gemini는 스탑 후 같은 PCM의 WAV 전체를 기존 `/live` 경로로 받습니다. Gemini의 `gemini-3.6-flash`, `gemini-3.1-flash-tts-preview`, 프롬프트와 문장별 TTS를 재사용합니다. 두 경로 모두 이전 대화 문맥을 넣지 않습니다.
- 스탑 전에는 출력 재생을 보류합니다. 선택한 모델 하나만 소리가 나고 다른 모델도 같은 브라우저 오디오 시계로 무음 예약하여 비교합니다. 녹음 트랙을 끈 다음 재생을 허용합니다.
- 앞쪽 작은 신호/무음만 임계값 256, pre-roll 200 ms로 처리합니다. 중간 쉼과 원본 PCM은 보존합니다. 초기 재생 여유 150 ms는 기존 앱과 같습니다. 기준 이하의 작은 음성이 잘릴 수 있어 원본 WAV도 저장할 수 있습니다.
- GPT-Live는 정지 후 30초의 무음을 보내 수신을 유지한 뒤 `session.close`를 요청하고 최대 15초 동안 종료 확인을 기다립니다. 최종 `usage.seconds`는 수신 종료 이벤트에서만 기록합니다. 문장 완료 신호가 없으므로 수신 종료를 번역 완료로 표현하지 않습니다. 이 무음 구간도 OpenAI 과금 시간에 포함됩니다.
- 파일은 실제 길이에 맞춰 전송합니다. 파일 전송 준비·마이크 권한·연결 대기는 별도 준비 시간이며 정지 후 지연에 포함하지 않습니다.

## 한 번만 필요한 연결

소유자의 Cloud Shell에서 `bash scripts/voice-comparison/setup-cloud-run.sh`를 실행합니다. 마스킹된 입력에 키를 붙여 넣으면 Secret Manager에 새 버전을 저장하고 기존 서비스의 `OPENAI_API_KEY`만 연결합니다. 서비스 계정에는 해당 비밀 하나를 읽는 권한만 추가합니다. 기존 환경 변수/비밀/Gemini 키를 나열하거나 덮어쓰지 않습니다. 프로젝트 및 최신 버전 100% 트래픽을 확인하지 못하면 중단합니다. 이 단계는 모델을 호출하지 않습니다.

인증은 Firebase Auth의 계정 조회로 토큰을 검증한 뒤 기존 소유자 이메일, 이메일 인증, 계정 활성 상태를 확인합니다. 토큰/키는 URL과 로그에 기록하지 않습니다. 서버 키가 없으면 모델 호출 전에 중단합니다. 한 인스턴스에서 소유자당 한 시험만 허용하며, 연결/입력/수신 시간과 입력·출력 크기에 상한을 둡니다. 취소/화면 이탈/연결 종료 시 두 업스트림 연결을 닫습니다. 이미 처리 중인 Gemini 요청의 취소·과금 중단은 보장하지 않습니다.

## 비교 및 판단

각 방향에서 5~15초 문장을 여러 번 시험하고, 먼저 들을 모델을 번갈아 선택합니다. 부정 표현, 숫자/시간, 알레르기, 조건, 고유명사, 문장 끝을 원음과 대조합니다. 같은 문장을 다시 말하면 입력이 달라지므로 완전히 같은 입력을 반복하려면 저장한 `source.wav`를 선택합니다. 녹음의 받아쓰기 정답이나 전체 기대 번역문을 추가로 주입하지 않습니다. 아래 개정 프롬프트에는 명시적인 용어와 읽기 예시가 있으므로 해당 표현의 재시험을 처음 보는 문장에 대한 일반화 성능으로 집계하지 않습니다.

### GPT 지시문 개정 `travel-2026-09-14`

소유자 전용 비교 화면의 GPT-Live 지시문만 보강합니다. 모델, 음성, PCM 전송, 재생 버퍼, 수신 시간과 기존 Gemini 경로는 유지합니다.

- 결제 상황의 会計/支払い와 산술/합계 산출의 計算을 구분하고, 결제 주체와 물건·결제 조건을 보존하도록 안내합니다.
- `유부초밥 ↔ いなり寿司`와 유부 단독 표현을 구분합니다.
- 泊/日의 구분과 `1泊2日`, `2泊3日`, `9日`의 읽기를 안내합니다. 한국어 출력에는 일본어 읽기 예시를 넣지 않습니다.
- 짧은 의미 단위의 서술어·부정·조건이 드러난 뒤 번역하도록 요청합니다. 스탑 시 생성을 강제로 시작하는 기능이 아니며, 스탑 전 생성이나 기다림 증가가 여전히 가능합니다.
- 보고서의 `promptEvidence.live`에 서버가 보낸 지시문의 버전과 SHA-256을 기록합니다. 이 값은 요청의 식별자이며 모델이 지시를 준수했다는 증거가 아닙니다. 개정 전 보고서에는 이 필드가 없습니다.

다음은 **평가 기준**이며 통과 결과가 아닙니다. API 출력, 속도, 음성 발음은 실제 실행 후 평가합니다. 같은 입력으로 개정 전후를 비교해야 합니다.

| 구분 | 한국어 입력 | 확인할 내용 |
| --- | --- | --- |
| 지정 표현 | 2박 3일 | `2泊3日`, 발음 `にはくみっか` |
| 지정 표현 | 이 물건을 계산해주세요. | 물건의 결제/회계 요청. `この商品の会計をお願いします` 등은 가능하며, `計算してください`만으로 옮기면 문맥 오류 |
| 지정 표현 | 유부초밥 | `いなり寿司`, 발음 `いなりずし` |
| 새로운 조합 | 3박 4일 예약을 2박 3일로 바꾸고 싶어요. | 3/4와 2/3 및 변경 방향 보존, 실제 숫자 읽기 확인 |
| 다른 의미 | 이 물건 세 개의 총액을 계산해주세요. | 합계 산출 요청을 결제 요청으로 바꾸지 않음 |
| 부정·조건 | 이 물건은 아직 계산하지 말고, 가격부터 알려주세요. | 결제를 요청하거나 이미 결제했다고 만들지 않음 |
| 다른 재료 표현 | 유부초밥 말고 유부만 들어 있나요? | 초밥과 유부를 구분하고 질문 유지 |
| 일본어 역방향 | 2泊3日で、いなり寿司を買いました。 | 2박 3일, 유부초밥을 한국어로 보존 |

짧은 쉼을 끼운 부정·조건 문장도 확인하되, 텍스트의 말줄임표만으로 실제 음성의 쉼을 시험했다고 하지 않습니다. 녹음 음량과 입력 해시를 맞추고, 초기 신호 시각·문장 완결·발음·재생 대기를 각각 확인합니다. 모의 서버 테스트 통과는 번역 품질 평가가 아닙니다. 예시를 프롬프트에 추가한 효과와 일반화 성능을 구분합니다.

보고서의 `stopToScheduledSpeechMs`는 임계값을 넘는 첫 신호의 브라우저 재생 예약 시각입니다. 물리 스피커·Bluetooth 지연은 측정하지 않으며, 무음 측정 모델은 실제로 들은 결과가 아닙니다. `signalSpanQueueGapsMs`는 첫/마지막 기준 신호 사이에서 재생 대기열이 비는 구간입니다. 음성 뒤 무음의 대기는 별도로 남깁니다. 0회만으로 실제 음성 끊김이 없다고 판정할 수 없습니다. 브라우저 오디오 시계가 멈춘 시험은 시간 비교에서 제외합니다.

이 시험의 Gemini 입력 인코딩은 PCM WAV로, 기존 메인 앱의 MediaRecorder 형식과 다릅니다. 모델·프롬프트·TTS는 같지만 기존 앱의 실제 휴대폰 지연과 완전히 같은 조건이라고 주장하지 않습니다. 텍스트가 맞아도 실제 음성과 끝까지 일치하는지 들어 봐야 합니다. 최종 채택에는 휴대폰의 소음·네트워크·일본어 역방향 시험이 필요합니다.

결과는 메모리에만 남고 수동 저장 시 기기로 내려받습니다. 사용자 녹음, 사진, 보고서, 키를 공개 GitHub에 올리지 않습니다. 저장소의 자동 테스트는 모의 제공자와 합성 PCM을 사용하며 유료 모델을 호출하지 않습니다.
